### results.json の独立再現

手続きの定義は `results.json` に無いため、候補を実装して特定した。
**A / B / C はいずれも「改善方向の棄却のみ」を数えている。** これが 3 手続きを同一の向きで
比較する条件であり、この条件でのみ報告値が再現する。

| セル | 指標 | 報告値 | 再現値 |
|---|---|---|---|
| p=0.5, n=30 | A 固定n・のぞき見なし | 0.0212 [0.0135, 0.0270] | 0.0212 [0.0135, 0.0270] |
| p=0.5, n=30 | B 固定n・のぞき見 | 0.0682 [0.0585, 0.0785] | 0.0682 [0.0585, 0.0785] |
| p=0.5, n=30 | C e-value・のぞき見 | 0.0211 [0.0165, 0.0260] | 0.0211 [0.0165, 0.0260] |
| p=0.5, n=30 | C 平均 n（条件付） | 13.2024 | 13.202 |
| p=0.5, n=200 | C e-value・のぞき見 | 0.0334 | 0.0335 |

## 監査上の留保（過大解釈を防ぐため明記する）

1. **A の H0 棄却率は 0.021 であり α=0.05 ではない。** 離散性による保守性である。
   したがって「C が α を下回る」は、既に保守的な基準との比較である。Ville の保証自体は M1 で
   独立に成立しているため結論は変わらないが、「C は A と同等に厳格」と読むのは誤りである。
2. **検出力の低下は大きい。** p=0.6, n_max=200 で A=0.787 → C=0.580（−0.21）。
   任意停止の自由は無料ではない。受領物の README も "including where it loses" と明記している。
3. **B の報告値は改善方向のみの計数である。** 両方向で数えると n=30 で 0.1363 となる。
   のぞき見による膨張は、報告値の約 2 倍が実体である。比較としては整合しているが、
   「のぞき見の危険度」を単独で引用する際は向きの条件を落としてはならない。
4. **受領物 README_2 自身が "Not validated in production. Zero known users.
   The 27 invariants are an opinion that compiles, not a result." と述べている。**
   本監査はこの自己申告と矛盾しない。実装が正しいことと、統治方式として妥当であることは別である。
5. `population.py` の `historical_gamma()` は 75/75 SOURCE_SELECTION_FAILED を
   `CLASS_H`（asserted, unverified, no artifact hash）として扱い、R0 = 0 と読む。
   **この読み自体は未検証の履歴事実に依存する。** 本キットの履歴判定（T-010）と同じ扱いを要する。
